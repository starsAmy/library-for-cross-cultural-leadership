原文 / THE STRUCTURE

让读者少
走一段路。

三条原则，三句原文。

文章中的任意一个层次的思想，都是对其下一层思想的总结与概括。每组中的思想，必须属于同一个逻辑范畴，并且必须按照逻辑顺序来组织。
01 / VERTICAL

纵向：疑问—回答

纵向的结构一定要提出“疑问—回答”式对话，让读者紧跟你的思路。

每一层都在替下一层问问题，而不是把材料按部门摊开。

02 / HORIZONTAL

横向：同一逻辑范畴

每组中的思想，必须属于同一个逻辑范畴。

同一层里混进“事实、判断、愿望”，读者就得替你重新分类。

03 / ORDER

顺序：时间、结构或程度

任何一组思想必须符合 3 种顺序：时间、结构或程度。

顺序不是审美。它告诉读者先看什么，以及为什么下一个理由该出现在这里。

一步实验 / 这封邮件叫什么

同一份季度复盘，只换标题。哪一种让人知道要做什么决定？

B 提出了问题，但没有带走答案。标题只负责开场，还是也能承担结论？

03

现场 / APPLY

先说答案，
不等于不顾场合。

跨文化 / 汇报

文章的“序言”应当采用讲故事的形式：先介绍读者熟悉的某些“背景”，说明发生的“冲突”，并由此引发读者的“疑问”，然后针对该“疑问”给出“答案”。

在更重关系和上下文的团队里，开口就抛结论会被读成不尊重过程。结构不必拆，顺序要调：先给共同背景，再把答案提到第二段。

第一页 SCQA，第二页开头给结论。背景不要绕超过两分钟。

领导力 / 项目复盘

每组中的思想必须按照逻辑顺序来组织。

复盘会很容易变成部门轮流传数据。主持人先收三句“对下一季度最重要的判断”，再让数据回来支撑判断，而不是让数据决定会议顺序。

会前收一页纸：结论、三条理由、一个需要拍板的问题。会议只讨论冲突与取舍。
